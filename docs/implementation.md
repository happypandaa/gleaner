# 拾闻首版实施报告

> 本报告记录首版实施。同日晚间的交互修订见文末「修订：主题由 AI 建立」，与正文冲突时以修订为准。

日期：2026-11-06。目录：`/Users/galen/dev/panda-project/gleaner`，分支：`develop`。

## 已实现

- 原生 HTML、CSS、ES 模块的静态网页应用，无第三方运行依赖、构建步骤、后端或 AI 接口；启用熊猫小抽屉 SDK，并声明 agent 运行规则。
- 数据库启动时以一个原子事务初始化六张表、索引、约束和 `schema_version = 1`；已存在的数据不重置，未来版本拒绝降级打开。
- 首次引导：创建主题或使用示例，复制含真实应用路径及时间的设置提示词，等待成功的 `setup` 记录，再进入第一期。复制动作不会伪造连接或定时成功。
- 今日：最近一期成功或部分成功运行、未更新提示、要点、搜索、主题及未读筛选、分组列表和阅读面板、额外信息、已读、收藏、忽略原因及撤销、备注失焦保存。
- 全部：标题、摘要、备注搜索；今天、7 天、30 天及自定义日期；14 天内容量日期条；主题与状态筛选、可移除条件、时间排序。每次查询最多 50 条，按需加载。
- 收藏：卡片和列表、主题和备注筛选、标题及备注搜索、收藏时间或发布时间排序。
- 主题：完整编辑、开启及暂停、顺序、额外记录和展示方式；显示统计和学到的偏好，支持删除偏好。删除主题需确认，历史内容及其收藏备注保留。
- 更新与记录：上次状态、定时安排、配图说明、设置与手动提示词、路径复制、时间选择、30 条一批的运行记录、内容格式异常提示。
- 深入了解及找类似的请求：记录为待处理，同一内容和类型的待处理请求去重；外部 AI 写回结果后可刷新显示。
- 每页手动刷新，窗口获得焦点及页面重新可见时刷新；不会因刷新覆盖主题草稿或备注。读取失败保留原页面并提供重试；图片按本地、HTTPS 原图、来源首字回退。
- `app/views/` 登记独立展示方式，未知方式回退列表；首版没有内置车价对比表。扩展说明见 `docs/views.md`。
- 后台每批最多 50 条检查超过 180 天的未收藏配图，仅处理规定目录的哈希缩略图；保留文字反馈、收藏及共享图片，删除失败恢复引用。收藏在数据库认领清理前保存时会优先保留。

没有因此改变应用的清单约定，也没有重建或修改平台。一次性测试项目已通过公开 CLI 删除，定向等待返回成功，项目列表和测试目录均已核对清理。用户原有项目与拾闻的 `data/` 未修改。

需要重新构建并启动包含 agent 支持及 `panda.context.get().projectRoot` 的熊猫小抽屉，再从「添加应用 → 本机文件夹」选择上述拾闻目录。

## 与设计的细节差异

- `learned.topic_id` 使用删除主题时级联删除该主题偏好，避免这些偏好在主题删除后被误当成全局偏好；历史内容仍按设计保留。
- 额外信息的 JSON 语法由数据库约束；对象形状及字符串值在查询时验证，无效内容被跳过并计数。主题关键词由程序保存为字符串数组。
- 首次引导完成状态由已保存主题与成功 `setup` 记录推断；当前会话在检测到首次成功后保留第三步按钮，重新打开已有简报时直接进入今日。不增加浏览器长期存储。
- 旧配图清理只接受文档规定的哈希路径，其他路径跳过，避免清理未知文件。

## 修订：主题由 AI 建立（2026-11-06 晚）

起因：拾闻无法感知用户是否已把提示词交给 AI，"已连接"依赖 AI 把 `trigger` 填成 `setup`，概念不真实，且会让直接说"更新简报"的用户卡在引导页；主题需要按不同行业的关注点设置，更适合在 AI 对话里说清楚并确认。

已改动：

- 去掉"连接 AI"判断、首次引导和 26 小时未更新提醒。今日页不再被替代，没有内容时显示空状态和"在 AI 里使用拾闻"链接；侧栏只描述运行记录（上次更新时间、进行中、可能中断、未完成）。
- 新增"在 AI 里使用拾闻"弹窗（`app/guide.js`），集中放三段提示词：开始使用、现在更新一次、每天自动更新（可选，并如实说明需要电脑开着、AI 应用在运行）。入口在侧栏、今日空状态和"今天还没更新"提示、主题页、记录页。
- "更新与记录"改为"记录"，只保留运行记录表，`schedule` 作为方式列的小字。旧的 `#updates` 地址自动转到记录页。
- 主题页去掉新建表单和示例主题，标题栏改为"想关注新的内容？告诉你的 AI"。保留调整、暂停、删除；表单下标注最近修改来源；删除确认说明偏好会一并删除。
- 数据库升级到版本 2：`topics` 新增 `updated_by`（`app`/`agent`，旧数据默认 `app`）。拾闻修改主题改为 `db.updateTopic(id, changes, expectedUpdatedAt)`，带 `updated_at` 版本检查；AI 刚改过时提示用户刷新后再改，不覆盖。原 `saveTopic` 移除，拾闻不再新建主题。
- `AGENTS.md`：新增「开始使用」（读现状 → 用户描述 → 一次确认后写库 → 更新第一期，不主动建定时任务，重复发送无害）和「管理主题」（只在用户明确要求时写、版本检查、以数据库而非对话记忆为准）；更新流程第 3 步识别用户改过的主题并清理冲突偏好，没有开启主题时只记录运行。
- `docs/design.md`、`docs/database.md`、`README.md` 同步更新。草图 `docs/design/05-updates.html`、`06-first-run.html` 为修订前版本，未改。

检查：数据层测试 18 项通过，新增版本 1→2 升级保留主题、`updated_by` 约束、拾闻修改标记来源且不覆盖 AI 较新修改。
