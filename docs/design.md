> 状态：首版已实现，真实平台与外部 AI 验收待完成；见 [实施报告](implementation.md)。日期：2026-11-06。
> 读者：负责实现的 AI。本文只写"做什么、为什么、做到什么程度"；具体代码结构由实现者决定，但不能违背本文的约束。界面草图在 `docs/design/`，用浏览器打开 `docs/design/index.html`。

## 0. 名称

- 中文名：**拾闻**（拾起散落的消息）。英文名 / 文件夹名：**Gleaner**（拾穗的人）。
- 文件夹已从 `agent-app` 重命名为 `/Users/galen/dev/panda-project/gleaner`。
- 名称由 Claude 拟定，用户尚未最终确认。如需改名，只改 `panda.json` 的 `app.name`、界面标题和本文，数据和表结构不受影响。

## 1. 一句话

**你的 AI 去收集，你在这里看。** 拾闻是熊猫小抽屉的第一个 agent 应用：用户自己的 AI（Claude、Codex、WorkBuddy 等）按用户定的主题去收集资讯，写进拾闻的数据库；拾闻负责展示、长期记录和收集用户反馈，AI 下次运行时读取反馈，越来越合用户口味。

它不是新闻 App：

| | 新闻 App | 拾闻 |
|---|---|---|
| 内容从哪来 | 平台推荐 | 用户自己的 AI 收集 |
| 主题 | 固定频道 | 用户用平常的话写 |
| 反馈 | 算法黑箱 | 收藏、不感兴趣、备注直接给 AI 看 |
| 历史 | 平台保存 | 全部在用户自己电脑上 |

## 2. 用户怎么用

用户的主场在 AI 工具里，拾闻是补充界面：

1. **设置一次**：在拾闻里写主题；把拾闻给出的"设置提示词"粘贴到自己的 AI 工具，让 AI 建一个每天运行的定时任务，并马上试跑一次。
2. **每天**：AI 按时运行，把新内容写进拾闻。用户打开拾闻浏览、收藏、标记不感兴趣、写备注。
3. **想深入时**：在某条内容上点"让 AI 深入了解"，留下请求；AI 下次运行时处理，结果显示在这条内容下面。
4. **想换个样子时**：用熊猫小抽屉的「按你的想法改」，让 AI 改拾闻本身，比如把车价主题改成对比表（见第 9 节）。

拾闻**不会**调起 AI、不读取 AI 的会话、不做定时调度。AI 和拾闻之间只通过这个文件夹里的文件和数据库交流。

## 3. 运行模型

### 3.1 一个文件夹，三方共用

拾闻的应用根目录 = 用户的 AI 的工作目录。熊猫小抽屉从这里运行界面；AI 在这里读 `AGENTS.md`、写数据库。

```
gleaner/                     ← 应用根目录，也是 AI 的工作目录
├── panda.json               ← 平台清单
├── AGENTS.md                ← 给 AI 的运行规则（第 7 节）
├── README.md                ← 给人看的简介
├── app/                     ← 界面程序（web.root），不需要构建
├── docs/
│   ├── design.md            ← 本文
│   ├── database.md          ← 表结构说明，以它为准（第 6 节）
│   └── design/              ← 界面草图
└── data/                    ← 平台数据目录（不进 Git）
    ├── main.sqlite
    └── attachments/
        └── images/YYYY-MM/  ← AI 存的配图缩略图
```

### 3.2 数据怎么流动

```
用户在拾闻里操作 ──► 拾闻写数据库（主题、收藏、不感兴趣、备注、请求）
                                   │
                         AI 运行时先读这些
                                   ▼
拾闻刷新后读数据库 ◄── AI 搜索后写数据库（新内容、配图、运行记录、学到的偏好）
```

- 数据库是唯一的长期存储，没有中间 JSON 文件。
- AI 不在线时，拾闻照常可用；用户的操作留在数据库里，等 AI 下次来读。
- AI 从外部写入数据库时，平台不会通知拾闻，所以拾闻要自己刷新（第 8.1 节）。

### 3.3 为什么 AI 可以直接写数据库

平台打开应用数据库的方式（已读代码确认，`crates/platform-core/src/database.rs`）：WAL 模式、5 秒等待、每次 SDK 请求是一个短事务、没有独占文件锁。因此拾闻开着窗口时，AI 用命令行读写同一个数据库是安全的，前提是 AI 遵守第 7 节的写入规则（设置等待时间、写事务要短、不改日志模式）。平台每次 SDK 请求最多等 5 秒，AI 如果长时间持有写事务，拾闻里收藏、备注等保存会失败，所以搜索和下载期间绝不能持有写事务。

## 4. 技术约定

- `runtime: "web"`，**不需要构建步骤**：`app/` 里直接是 HTML、CSS、原生 ES 模块。理由：用户会经常让 AI 改界面，没有构建步骤就不会出现"改了没生效"的问题。不引入前端框架；如确需第三方库，把文件放进 `app/vendor/`，不用 npm。
- 通过 `<script src="/_platform/sdk.js"></script>` 使用 `window.panda`：数据库用 `panda.db`，配图用 `panda.files`。
- 不需要后端、不需要 API Key、不需要声明网络访问（拾闻自己不联网；远程配图走 https，平台安全策略已允许）。
- `.gitignore` 必须包含 `data/`，用户的简报、配图、数据库永远不进 Git。
- 界面全部中文，不出现 Git、SQL、JSON 等开发词汇（设置提示词里可以出现文件名，因为那是给 AI 看的）。

`panda.json` 草案（`agent` 字段平台已支持，提交 `d3840c0`）：

```json
{
  "manifestVersion": 1,
  "runtime": "web",
  "app": {
    "name": "拾闻",
    "version": "0.1.0",
    "description": "你的 AI 去收集，你在这里看：按你写的主题每天整理资讯，收藏和反馈都留在本机，AI 会越来越懂你。"
  },
  "web": { "root": "app", "entry": "index.html" },
  "platform": { "sdkApiVersion": 1 },
  "agent": { "instructions": "AGENTS.md" },
  "documentation": {
    "readme": "README.md",
    "development": "docs/design.md",
    "database": "docs/database.md"
  }
}
```

## 5. 写入分工（最重要的约束）

只有一张主表 `items`，AI 和拾闻都写它，但**按列分工**。分工的目的：AI 更新内容时永远不会覆盖用户的标记。

| 数据 | 谁写 | 谁读 |
|---|---|---|
| 主题设置 `topics` | 拾闻 | AI |
| 内容 `items` 的内容列 | AI（只新增行） | 拾闻 |
| 内容 `items` 的用户列（已读、收藏、不感兴趣、备注） | 拾闻 | AI |
| 运行记录 `runs` | AI | 拾闻 |
| 请求 `requests` 的请求列 | 拾闻 | AI |
| 请求 `requests` 的结果列 | AI | 拾闻 |
| 学到的偏好 `learned` | AI 写；拾闻只能删除（用户点"删除这条"） | 拾闻、AI |
| 表结构 | 拾闻程序在启动时创建和升级 | 双方 |

硬性规则：

1. AI 对 `items` 只用 `INSERT` 或 `INSERT OR IGNORE` 新增内容，**禁止** `INSERT OR REPLACE`、`REPLACE`、`DELETE`。`REPLACE` 会先删旧行，用户的收藏和备注会丢失。
2. AI 日常运行**不改表结构**。表结构只在用户要求修改应用时改，并且同时改程序和 `docs/database.md`（第 9.3 节）。
3. 拾闻只更新 `items` 的用户列。两个例外：配图清理时把 `image_path` 置空（第 6.7 节）；删除主题时该主题内容的 `topic_id` 置空（第 6.2 节，可用外键 `ON DELETE SET NULL` 实现）。

## 6. 数据设计

以下是第一版表结构，实现者把它写进 `docs/database.md` 并由程序在启动时创建。时间一律存 ISO 8601 文本（带时区，如 `2026-11-06T08:12:00+08:00`）。

### 6.1 `meta`

| 列 | 说明 |
|---|---|
| `key` TEXT 主键 | 目前只有 `schema_version` |
| `value` TEXT | |

程序启动时读 `schema_version`，按版本依次升级。第一版为 `1`。

### 6.2 `topics`（拾闻写）

| 列 | 说明 |
|---|---|
| `id` INTEGER 主键 | |
| `name` TEXT 非空 | 主题名称，如"新能源车价格" |
| `description` TEXT 非空 | 我关心什么，用户的原话 |
| `keywords` TEXT | 关键词，JSON 字符串数组，默认 `[]` |
| `sources` TEXT | 优先的来源，自由文本 |
| `excludes` TEXT | 不要的内容，自由文本 |
| `extra_fields` TEXT | 需要额外记录的信息，自由文本，如"车型、现价、降价金额、优惠截止日期"（第 9.1 节） |
| `max_items` INTEGER | 每次最多几条，默认 6，范围 1–20 |
| `view` TEXT | 展示方式，默认 `list`（第 9.2 节） |
| `enabled` INTEGER | 1 开启 / 0 暂停，默认 1 |
| `sort_order` INTEGER | 显示顺序 |
| `created_at`、`updated_at` TEXT | |

删除主题时：主题行删除，它的历史内容保留，`items.topic_id` 置空，界面显示为"已删除的主题"。

### 6.3 `items`

AI 写的内容列：

| 列 | 说明 |
|---|---|
| `id` INTEGER 主键 | |
| `run_id` INTEGER | 哪一次运行写入的 |
| `topic_id` INTEGER | 属于哪个主题 |
| `title` TEXT 非空 | |
| `url` TEXT 非空、**唯一** | 原文链接；唯一约束同时实现去重 |
| `source` TEXT | 来源名称，如"汽车资讯" |
| `published_at` TEXT | 原文发布时间，不确定可空 |
| `summary` TEXT 非空 | AI 写的中文摘要，2–4 句 |
| `reason` TEXT | 为什么推给这位用户，一句话 |
| `importance` INTEGER | 1 一般 / 2 值得看 / 3 重要，默认 2 |
| `image_path` TEXT | 本机配图，相对 `data/attachments/` 的路径 |
| `image_url` TEXT | 原图地址，备用 |
| `extra` TEXT | 额外信息，JSON 对象，默认 `{}`，键名用主题 `extra_fields` 里的原词，值一律是字符串 |
| `collected_at` TEXT 非空 | 写入时间 |

拾闻写的用户列：

| 列 | 说明 |
|---|---|
| `is_read` INTEGER | 默认 0 |
| `is_starred` INTEGER | 默认 0 |
| `starred_at` TEXT | |
| `is_dismissed` INTEGER | 不感兴趣，默认 0 |
| `dismiss_reason` TEXT | `和主题无关`、`来源不可靠`、`内容太旧`、`重复了` 之一，可空 |
| `note` TEXT | 用户备注，AI 也会读 |
| `user_updated_at` TEXT | 用户最后一次操作这条的时间 |

约束：`extra` 和 `keywords` 加 `json_valid` 检查；`importance` 加范围检查；`dismiss_reason` 加取值检查。约束的作用是让写错的数据直接被数据库拒绝，而不是在界面上出错。

索引：`collected_at`、`topic_id`、`is_starred`。

### 6.4 `runs`（AI 写）

| 列 | 说明 |
|---|---|
| `id` INTEGER 主键 | |
| `started_at` TEXT 非空 | |
| `finished_at` TEXT | 结束时写 |
| `agent` TEXT | AI 自报的工具名，如 `Claude`、`Codex`、`WorkBuddy` |
| `trigger` TEXT | `setup`（第一次试跑）/ `scheduled`（定时）/ `manual`（用户叫的） |
| `status` TEXT | `running` / `done` / `partial` / `failed` |
| `schedule` TEXT | AI 自报的定时安排，如"每天 08:00"；没有定时任务时为空 |
| `added`、`skipped` INTEGER | 新增条数、因重复跳过的条数 |
| `images_saved`、`images_failed` INTEGER | |
| `digest` TEXT | 这一期的"今日要点"，AI 写的 1–3 句 |
| `message` TEXT | 给用户看的说明，失败或部分完成时写原因 |

AI 开始时单独插入一行 `status = running` 并立即提交，拾闻据此显示"AI 正在更新…"；收集完成后，在写入内容的同一个短事务里把这行更新为最终状态；写入失败时单独把它更新为 `failed`。拾闻用这张表显示连接状态和更新状态（第 8.6 节）。

### 6.5 `requests`

| 列 | 谁写 | 说明 |
|---|---|---|
| `id` INTEGER 主键 | 拾闻 | |
| `kind` TEXT | 拾闻 | `deep_dive`（深入了解）/ `similar`（找类似的） |
| `item_id` INTEGER | 拾闻 | 针对哪一条 |
| `text` TEXT | 拾闻 | 用户补充的话，可空 |
| `created_at` TEXT | 拾闻 | |
| `status` TEXT | AI | `pending`（默认）/ `done` / `failed` |
| `result` TEXT | AI | 处理结果，纯文本；找到的新内容另外写入 `items`，并在这里列出标题 |
| `run_id`、`finished_at` | AI | |

### 6.6 `learned`（AI 写，拾闻可删）

| 列 | 说明 |
|---|---|
| `id` INTEGER 主键 | |
| `topic_id` INTEGER | 可空，空表示对所有主题都适用 |
| `text` TEXT 非空 | 一句话，如"常标记不感兴趣：融资消息" |
| `updated_at` TEXT | |

每个主题最多 10 条。AI 每次运行根据最近的反馈更新这张表（可以改自己写的行、删自己写的行）。

### 6.7 配图

- AI 下载原文配图，缩成最长边 640 像素以内（macOS 自带 `sips` 可以做），存到 `data/attachments/images/YYYY-MM/<链接哈希>.jpg`（链接 SHA-1 的前 16 位十六进制；配图在写库之前下载，那时还没有内容 id），把相对路径写入 `image_path`，同时把原图地址写入 `image_url`。
- 下载或缩图失败：`image_path` 留空，只写 `image_url`，并计入 `images_failed`。
- 拾闻显示顺序：`image_path`（用 `panda.files.url`）→ `image_url`（仅 https）→ 来源名称首字的色块。
- 清理：拾闻在启动时检查，未收藏且 `collected_at` 超过 180 天的内容，删除配图文件并把 `image_path` 置空，文字保留。清理在后台进行，不阻塞界面，失败只记在控制台。此功能优先级低（第 11 节）。

## 7. `AGENTS.md`

`AGENTS.md` 是 AI 每次在这个文件夹工作时的规则。实现者按下面的草稿写成正式文件，可以调整措辞，但规则不能少。表结构细节写在 `docs/database.md`，`AGENTS.md` 只引用它，不重复。

````markdown
# 拾闻：给 AI 的运行规则

拾闻是用户的资讯简报应用。你负责按用户的主题收集内容并写入数据库；拾闻负责展示和记录用户反馈。

## 你可能被要求做的三类事

1. **更新简报**（用户说"更新简报"，或定时任务触发）：按下面"更新流程"做。
2. **处理请求**：更新流程的第 3 步会处理，不需要单独流程。
3. **修改拾闻本身**（用户说"把列表改成卡片""车价主题做成对比表"等）：这是改程序，不是更新简报。先读 `docs/design.md` 和 `docs/database.md`，按熊猫小抽屉平台说明的修改流程做；需要改表结构时，同时改程序里的升级代码和 `docs/database.md`。

用户没有明确要求时，不要改 `app/`、`panda.json`、`AGENTS.md`、`docs/` 里的任何文件。

## 更新流程

0. 数据库是 `data/main.sqlite`。如果它不存在，或里面没有 `topics` 表，说明用户还没打开过拾闻：不要自己建库建表，告诉用户先在熊猫小抽屉里打开一次拾闻，然后结束。
1. 用命令行打开数据库，**每次都先设置等待时间**：
   `sqlite3 -cmd ".timeout 5000" data/main.sqlite`
2. **开始**：在 `runs` 单独插入一行并立即提交：`status='running'`、`trigger`（定时任务填 `scheduled`，用户当面叫你填 `manual`，第一次设置时填 `setup`）、`agent` 填你的工具名、`schedule` 填你的定时安排（没有就空）。记下这行的 `id`。
3. **读取**（只读查询，不开写事务）：
   - 开启的主题：`SELECT * FROM topics WHERE enabled = 1 ORDER BY sort_order`
   - 最近 30 天的反馈：收藏的、不感兴趣的（含原因）、有备注的内容的标题、来源、链接
   - `learned` 表
   - 最近 30 天已有的链接（用于去重）
   - 待处理的请求：`SELECT * FROM requests WHERE status = 'pending'`
   不要读取全部历史；只有用户明确要求回顾历史时，才做更大范围的只读查询。
4. **处理请求**（这一步不写数据库，结果先整理好，留到第 7 步写入）：深入了解就围绕那条内容查更多资料，整理成 `result`；找类似的就把找到的内容作为新内容准备好，`result` 里列出标题。处理不了的请求记下原因，第 7 步标为 `failed`。
5. **按主题收集内容**（这一步不写数据库）：
   - 每个主题不超过它的 `max_items` 条，宁缺毋滥。
   - 遵守 `description`、`excludes`、`sources`，参考反馈和 `learned`。
   - 跳过已有链接和明显重复的内容。
   - `summary` 用中文写 2–4 句，说清楚这条内容讲了什么；`reason` 用一句话说明为什么推给这位用户。
   - 主题的 `extra_fields` 不为空时，把这些信息写进 `extra`，键名用 `extra_fields` 里的原词，值写成字符串；查不到的键不写。
6. **配图**（这一步不写数据库）：下载原文配图，用 `sips -Z 640` 缩小后存到 `data/attachments/images/YYYY-MM/<链接哈希>.jpg`（链接 SHA-1 的前 16 位，可用 `shasum`），准备写入 `image_path`；同时准备好原图地址 `image_url`。失败就只写 `image_url`。
7. **写入**（一个短事务，几秒内完成）：`BEGIN IMMEDIATE;` 然后依次：
   - 用 `INSERT OR IGNORE` 写入第 4、5 步准备好的新内容；
   - 更新请求的 `status`、`result`、`run_id`、`finished_at`；
   - 根据最近的反馈更新 `learned`（每个主题最多 10 条，一句话一条）；
   - 更新第 2 步那行 `runs`：`finished_at`、`status`（全部完成 `done`，部分主题失败 `partial`，什么也没写成 `failed`）、各项计数、`digest`（今日要点 1–3 句）、`message`（有问题时说明原因）；
   - `COMMIT;`
   事务里只执行写库语句，不做搜索、下载、缩图或其他耗时操作。
8. **写入失败时**：确认事务已回滚，再单独把第 2 步那行 `runs` 更新为 `failed`，在 `message` 里写原因。已经下载的配图可以留着，下次同一链接会复用。

## 写入规则（必须遵守）

- 写库只在三个时刻：开始时插入运行记录（单独提交）；收集和下载全部完成后，内容、请求结果、学到的偏好和运行记录的最终状态放进**一个短事务**（第 7 步）；失败时单独标记运行记录。搜索、下载、缩图期间**不持有写事务**：拾闻的每次保存最多等 5 秒，长事务会让用户的收藏、备注保存失败。
- 新增内容只用 `INSERT` 或 `INSERT OR IGNORE`。**禁止** `INSERT OR REPLACE`、`REPLACE`、`DELETE FROM items`。
- 不修改 `items` 的这些列：`is_read`、`is_starred`、`starred_at`、`is_dismissed`、`dismiss_reason`、`note`、`user_updated_at`。它们是用户的。
- 不修改 `topics` 表。
- 更新简报时不改表结构，不执行 `PRAGMA journal_mode`、`VACUUM`，不删除 `main.sqlite-wal`、`main.sqlite-shm`。
- 配图只写进 `data/attachments/images/`，不在 `data/` 其他位置建文件。
- 数据库报"被锁"时等几秒重试，不要删除任何文件。

表结构以 `docs/database.md` 为准。
````

## 8. 界面

草图在 `docs/design/`。草图表达结构、内容和文案方向；视觉以紧凑为原则：正文 13px，行高 1.5，页面边距 14–18px，控件高 28–32px。

### 8.1 全局

- 左侧导航：今日、全部、收藏、主题、更新与记录。底部是更新状态（第 8.6 节），点击进入"更新与记录"。
- **刷新**：每页标题栏有刷新按钮；窗口重新获得焦点、页面重新可见时也自动刷新一次。刷新只重新查询数据库，不打断用户正在编辑的输入。
- 有新内容时（刷新后比之前多），导航"今日"旁显示新条数，不弹窗。
- 所有列表分页或按需加载，每次 50 条，不一次性读全部历史。

### 8.2 今日（`01-today.html`）

- 显示最近一次成功运行写入的内容。如果今天还没有运行，顶部提示"今天还没更新，下面是 11 月 5 日的内容"，内容照常显示。
- 顶部：日期、条数、未读数；搜索框（只搜今日）；"全部标为已读"。
- 今日要点：显示这次运行的 `digest`。
- 主题筛选：全部、未读、各主题。
- 左边列表、右边阅读：
  - 列表按主题分组，每行：缩略图（76×52）、标题（未读加粗）、来源 · 时间、未读圆点、收藏标记；有 `extra` 时在标题下显示最多 3 个"额外信息"标签。
  - 点一行，右边显示大图、主题、标题、来源时间、摘要、额外信息、"为什么给你"、操作按钮、备注框，并把这条标为已读。
  - 操作：收藏 / 已收藏、不感兴趣、打开原文（系统浏览器）、复制链接、让 AI 深入了解。
  - 不感兴趣后：这条在列表里折叠成一行"已忽略 · 撤销"，右边显示四个原因按钮（可选、可改）。
  - 备注失焦时自动保存，旁边显示"AI 下次更新时会看到"。
- 主题的 `view` 不是 `list` 时，该主题分组使用对应的展示方式（第 9.2 节）。

### 8.3 全部（`02-all.html`）

- 搜索：标题、摘要、备注，模糊匹配。
- 日期：今天 / 近 7 天 / 近 30 天 / 自定义（起止日期）。
- 最近 14 天的日期条：每天一格，显示条数柱和数字，点击只看那天，当前范围高亮。
- 主题、状态（全部、未读、收藏、已忽略）、排序（最新、最早）。
- 当前筛选显示成可移除的标签，加"清除全部"，右侧显示结果条数。
- 结果按日期分组，每行：小缩略图（56×40）、标题（搜索词高亮）、一行摘要、主题标签、来源 · 时间、收藏标记。点击打开阅读面板（可复用今日的右侧面板，或跳到对应位置，由实现者选择）。

### 8.4 收藏（`03-favorites.html`）

- 卡片网格（每张最小宽 220px），图片 16:9；也可切换为列表。
- 卡片：主题、标题、来源 · 发布日期、备注（如有）、收藏于何时。
- 筛选：主题、"有备注"；搜索标题和备注；排序：收藏时间、发布时间。

### 8.5 主题（`04-topics.html`）

- 左边主题列表（名称、描述、开启 / 暂停、最近一次条数、收藏数），右边编辑表单。
- 表单：主题名称、每次最多几条、我关心什么、关键词、优先的来源、不要的内容、**额外记录**（自由文本，提示"比如：车型、现价、降价金额、优惠截止日期"）、**展示方式**（下拉，默认"列表"，列出 `app/views/` 里已有的方式）。
- "AI 从你的反馈里学到的"：列出 `learned`，每条可删除。
- 删除主题要确认，并说明"历史内容会保留"。
- 第一次打开、还没有主题时，提供"用示例主题开始"：一键创建"AI 工具动态"，可随时删除。

### 8.6 更新与记录（`05-updates.html`）

- 当前状态三格：上次更新（时间、状态、AI 工具、新增条数）、自动更新（AI 自报的定时安排）、配图（保存在本机，只存缩略图）。
- 状态判断（侧栏底部也用同一规则）：
  - 没有任何运行记录 → "还没有连接 AI"，引导去设置。
  - 最近一行是 `running` 且开始不到 1 小时 → "AI 正在更新…"。超过 1 小时 → "上次更新可能中断了"。
  - 最近一次 `done` 或 `partial` 在 26 小时内 → 绿点 + "今天 08:12 已更新"。
  - 超过 26 小时没有成功更新 → 橙点 + "已经 2 天没有更新"，提示检查 AI 工具里的定时任务。
- 两种更新方式（只显示提示词和复制按钮，**拾闻不调起 AI**）：
  - **每天自动更新（推荐）**：选择每天几点（默认 08:00），显示"设置提示词"和复制按钮。
  - **现在手动更新一次**：显示"手动更新提示词"和复制按钮；并说明"也可以直接在 AI 工具里说'更新简报'"。
  - 每段提示词旁显示本应用文件夹的路径和"复制路径"。路径来自 `(await panda.context.get()).projectRoot`（平台已支持，提交 `d3840c0`）。
- 运行记录表：时间、AI 工具、方式（定时 / 手动 / 设置）、结果（新增、跳过、配图、说明）、状态。最近 30 条，可加载更多。

提示词文案（`<路径>`、`<时间>` 为占位）：

- 设置提示词：
  > 请在这个文件夹里工作：`<路径>`。先读其中的 AGENTS.md。然后：1. 马上按 AGENTS.md 更新一次简报，运行记录的 trigger 填 setup；2. 帮我建一个每天 `<时间>` 运行的定时任务，工作目录设为这个文件夹，任务内容是"按 AGENTS.md 更新简报"，并把定时安排写进运行记录的 schedule。如果你不支持定时任务，直接告诉我。
- 手动更新提示词：
  > 请在 `<路径>` 里按 AGENTS.md 更新一次简报。

### 8.7 第一次打开（`06-first-run.html`）

三步引导，完成一步打一个勾：

1. **写一个主题**（或用示例主题开始）。
2. **连接你的 AI**：显示设置提示词、复制按钮、选择时间；复制后状态变为"等待 AI 第一次运行…"，并说明"在你的 AI 工具里粘贴发送，完成后回到这里"。
3. **看第一期**：检测到第一条 `trigger = setup` 的运行记录后，显示"已连接 · Claude · 每天 08:00"，按钮"去看今日简报"。

引导在三步完成前替代"今日"页；之后不再出现，可以在"更新与记录"里重新查看提示词。

### 8.8 异常提示

| 情况 | 提示 |
|---|---|
| 数据库里有不完整的内容（如 `extra` 不是对象） | 跳过这条，"更新与记录"里显示"有 N 条内容格式不对，已跳过" |
| 配图文件不存在 | 静默改用原图地址或来源首字，不报错 |
| 运行失败 | 侧栏状态变红，"更新与记录"显示 AI 写的 `message` |
| 长时间没有更新 | 见 8.6 |
| 数据库读取失败 | 页面中央说明"暂时读不到数据"，附"重试"，不清空已显示的内容 |

## 9. 通用版与定制

不同信息关注点不同（车价关心现价和优惠截止，出行关心线路和生效时间）。拾闻做一个通用版，再留出两层定制。

### 9.1 第一层：额外信息（不改程序）

用户在主题里写"额外记录"，AI 把这些信息写进 `items.extra`，通用列表把它们显示成标签。例如车价主题写"车型、现价、降价金额、优惠截止日期"，列表行显示"现价 15.98 万 · 降 0.8 万 · 截止 11/30"。大部分主题做到这一层就够了。

### 9.2 第二层：展示方式（AI 改程序）

- 程序里有一个清楚的"展示方式"登记处：`app/views/` 下每种展示方式一个文件，`app/views/index.js` 登记 `id → 名称、渲染函数`。
- 通用列表 `list` 是默认方式。一个主题选了别的方式后，今日和全部页面里该主题的内容用这种方式渲染；阅读面板、收藏、搜索不受影响。
- 新增一种展示方式 = 新增一个文件 + 在登记处加一行。不改通用部分。
- 在 `docs/design.md` 或单独的 `docs/views.md` 写清楚怎么新增，AI 修改前先读。

### 9.3 示范：车价对比表

第一版**不内置**车价对比表。它用来演示第二层：用户用「按你的想法改」对 AI 说"车价主题做成对比表"，AI 新增 `price-table` 展示方式。草图 `07-car-generic.html`（通用列表 + 额外信息标签）和 `08-car-custom.html`（定制后的对比表）展示改前改后。实现者在完成通用版后，可以自己按这个说法试做一次，用来检验第二层设计是否顺手，结果作为报告的一部分。

需要改表结构的定制（比如把"现价"升级成正式数字列以便排序），按这个顺序：程序里加升级步骤 → `meta.schema_version` 加一 → 更新 `docs/database.md` → 必要时更新 `AGENTS.md` 的写入说明。只加列、加表，不删已有的；必须删除或清空数据时，先向用户说明影响并取得同意。

## 10. 不做的

- 调起 AI、读取 AI 会话、定时调度、推送通知。
- 自己联网抓取或调用任何 AI 接口。
- 中间 JSON 文件、文件变化监听。
- 账号、同步、多设备。
- 全文搜索引擎（数据量在几万条内，模糊匹配足够）。
- 内置车价对比表或其他主题专属界面（第 9.3 节）。

## 11. 优先级与验收

**第一优先（demo 必须有）**

- 程序启动时创建全部表，`schema_version = 1`；`docs/database.md` 完整。
- `AGENTS.md` 按第 7 节写好。
- 今日（含阅读面板、收藏、不感兴趣及原因、备注）、主题（含示例主题、额外记录、展示方式下拉）、更新与记录（状态、提示词复制、运行记录）、第一次打开的引导。
- 刷新按钮和获得焦点自动刷新。
- 额外信息标签。
- 验收：在一个空的拾闻里，按引导写主题、复制设置提示词交给真实的 AI 工具，AI 运行后刷新能看到内容和配图；收藏、不感兴趣、备注后再让 AI 更新一次，AI 的运行记录或 `learned` 体现了反馈；AI 运行期间开着拾闻窗口操作，不出现错误或数据丢失。

**第二优先**

- 全部页（搜索、日期条、筛选）、收藏页。
- 请求：让 AI 深入了解、找类似的。
- 展示方式登记处，并试做一次车价对比表（第 9.3 节）。

**第三优先**

- 配图 180 天清理。
- 收藏页列表视图。

完成后提交报告：做了哪些、和本文不一致的地方及原因、实测过的 AI 工具和结果、未完成项。
