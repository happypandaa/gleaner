> 状态：首版已实现。日期：2026-11-06。

> 修订（2026-11-08）：第一版不做定时更新和「现在更新」，弹窗只留「开始使用」和常见问题；拾闻打不开时显示真实原因，引导用户交给 AI。

## 0. 名称

- 中文名：**拾闻**（拾起散落的消息）。英文名 / 文件夹名：**Gleaner**（拾穗的人）。
- 应用目录名为 `gleaner`，运行路径由平台提供。
- 名称由 Claude 拟定，用户尚未最终确认。如需改名，只改 `panda.json` 的 `app.name`、界面标题和本文，数据和表结构不受影响。

## 1. 一句话

**你的 AI 去收集，你在这里看。** 拾闻是熊猫小抽屉的第一个 agent 应用：用户自己的 AI（Claude、Codex、WorkBuddy 等）按用户定的主题去收集资讯，写进拾闻的数据库；拾闻负责展示、长期记录和收集用户反馈，AI 下次运行时读取反馈，越来越合用户口味。

它不是新闻 App：

| | 新闻 App | 拾闻 |
|---|---|---|
| 内容从哪来 | 平台推荐 | 用户自己的 AI 收集 |
| 主题 | 固定频道 | 用户用平常的话写 |
| 反馈 | 算法黑箱 | 收藏、不感兴趣、备注直接给 AI 看 |
| 历史 | 平台保存 | 全部在用户自己电脑上 |

## 2. 用户怎么用

用户的主场在 AI 工具里，拾闻是补充界面：

1. **开始一次**：从拾闻的"在 AI 里使用拾闻"复制一句开场白发给自己的 AI 工具，在 AI 里用自己的话说清想关注什么。AI 把主题整理好给用户确认，确认后写入拾闻并马上更新第一期。
2. **之后**：想看新内容时，在和 AI 的对话里说“更新简报”。第一版不做定时更新。AI 把新内容写进拾闻。用户打开拾闻浏览、收藏、标记不感兴趣、写备注。
3. **想深入时**：在某条内容上点"让 AI 深入了解"，留下请求；用户下次让 AI 更新简报时处理，结果显示在这条内容下面。
4. **想换个样子时**：用熊猫小抽屉的「按你的想法改」，让 AI 改拾闻本身，比如把车价主题改成对比表（见第 9 节）。

拾闻**不会**调起 AI、不读取 AI 的会话、不做定时调度。AI 和拾闻之间只通过这个文件夹里的文件和数据库交流。

## 3. 运行模型

### 3.1 一个文件夹，三方共用

拾闻的应用根目录 = 用户的 AI 的工作目录。熊猫小抽屉从这里运行界面；AI 在这里读 `AGENTS.md`、写数据库。

```
gleaner/                     ← 应用根目录，也是 AI 的工作目录
├── panda.json               ← 平台清单
├── AGENTS.md                ← 给 AI 的运行规则（第 7 节）
├── README.md                ← 给人看的简介
├── app/                     ← 界面程序（web.root），不需要构建
├── docs/
│   ├── design.md            ← 本文
│   ├── database.md          ← 表结构说明，以它为准（第 6 节）
│   └── design/              ← 界面草图
└── data/                    ← 平台数据目录（不进 Git）
    ├── main.sqlite
    └── attachments/
        └── images/YYYY-MM/  ← AI 存的配图缩略图
```

### 3.2 数据怎么流动

```
用户在拾闻里操作 ──► 拾闻写数据库（主题、收藏、不感兴趣、备注、请求）
                                   │
                         AI 运行时先读这些
                                   ▼
拾闻刷新后读数据库 ◄── AI 搜索后写数据库（新内容、配图、运行记录、学到的偏好）
```

- 数据库是唯一的长期存储，没有中间 JSON 文件。
- AI 不在线时，拾闻照常可用；用户的操作留在数据库里，等 AI 下次来读。
- AI 从外部写入数据库时，平台不会通知拾闻，所以拾闻要自己刷新（第 8.1 节）。

### 3.3 为什么 AI 可以直接写数据库

平台打开应用数据库的方式（已读代码确认，`crates/platform-core/src/database.rs`）：WAL 模式、5 秒等待、每次 SDK 请求是一个短事务、没有独占文件锁。因此拾闻开着窗口时，AI 用命令行读写同一个数据库是安全的，前提是 AI 遵守第 7 节的写入规则（设置等待时间、写事务要短、不改日志模式）。平台每次 SDK 请求最多等 5 秒，AI 如果长时间持有写事务，拾闻里收藏、备注等保存会失败，所以搜索和下载期间绝不能持有写事务。

## 4. 技术约定

- 统一清单 v2，不声明 `backend`，**不需要构建步骤**：`app/` 里直接是 HTML、CSS、原生 ES 模块。理由：用户会经常让 AI 改界面，没有构建步骤就不会出现"改了没生效"的问题。不引入前端框架；如确需第三方库，把文件放进 `app/vendor/`，不用 npm。
- 通过 `<script src="/_platform/sdk.js"></script>` 使用 `window.panda`：数据库用 `panda.db`，配图用 `panda.files`。
- 不需要后端、不需要 API Key、不需要声明网络访问（拾闻自己不联网；远程配图走 https，平台安全策略已允许）。
- `.gitignore` 必须包含 `data/`，用户的简报、配图、数据库永远不进 Git。
- 界面全部中文，不出现 Git、SQL、JSON 等开发词汇（设置提示词里可以出现文件名，因为那是给 AI 看的）。

`panda.json` 草案（`agent` 字段平台已支持，提交 `d3840c0`）：

```json
{
  "manifestVersion": 2,
  "app": {
    "name": "拾闻",
    "version": "0.1.0",
    "description": "你的 AI 去收集，你在这里看：按你写的主题每天整理资讯，收藏和反馈都留在本机，AI 会越来越懂你。"
  },
  "web": { "root": "app", "entry": "index.html" },
  "platform": { "sdkApiVersion": 1 },
  "agent": { "instructions": "AGENTS.md" },
  "documentation": {
    "readme": "README.md",
    "development": "docs/design.md",
    "database": "docs/database.md"
  }
}
```

## 5. 写入分工（最重要的约束）

只有一张主表 `items`，AI 和拾闻都写它，但**按列分工**。分工的目的：AI 更新内容时永远不会覆盖用户的标记。

| 数据 | 谁写 | 谁读 |
|---|---|---|
| 主题设置 `topics` | AI（仅在用户于对话中要求时新建、修改、删除）；拾闻（修改、删除，不新建） | 双方 |
| 内容 `items` 的内容列 | AI（只新增行） | 拾闻 |
| 内容 `items` 的用户列（已读、收藏、不感兴趣、备注） | 拾闻 | AI |
| 运行记录 `runs` | AI | 拾闻 |
| 请求 `requests` 的请求列 | 拾闻 | AI |
| 请求 `requests` 的结果列 | AI | 拾闻 |
| 学到的偏好 `learned` | AI 写；拾闻只能删除（用户点"删除这条"） | 拾闻、AI |
| 表结构 | 拾闻程序在启动时创建和升级 | 双方 |

硬性规则：

1. AI 对 `items` 只用 `INSERT` 或 `INSERT OR IGNORE` 新增内容，**禁止** `INSERT OR REPLACE`、`REPLACE`、`DELETE`。`REPLACE` 会先删旧行，用户的收藏和备注会丢失。
2. AI 日常运行**不改表结构**。表结构只在用户要求修改应用时改，并且同时改程序和 `docs/database.md`（第 9.3 节）。
3. 拾闻只更新 `items` 的用户列。两个例外：配图清理时把 `image_path` 置空（第 6.7 节）；删除主题时该主题内容的 `topic_id` 置空（第 6.2 节，可用外键 `ON DELETE SET NULL` 实现）。

## 6. 数据设计

以下是第一版表结构，实现者把它写进 `docs/database.md` 并由程序在启动时创建。时间一律存 ISO 8601 文本（带时区，如 `2026-11-06T08:12:00+08:00`）。

### 6.1 `meta`

| 列 | 说明 |
|---|---|
| `key` TEXT 主键 | 目前只有 `schema_version` |
| `value` TEXT | |

程序启动时读 `schema_version`，按版本依次升级。第一版为 `1`。

### 6.2 `topics`（AI 按用户要求建立，双方可改）

| 列 | 说明 |
|---|---|
| `id` INTEGER 主键 | |
| `name` TEXT 非空 | 主题名称，如"新能源车价格" |
| `description` TEXT 非空 | 我关心什么，用户的原话 |
| `keywords` TEXT | 关键词，JSON 字符串数组，默认 `[]` |
| `sources` TEXT | 优先的来源，自由文本 |
| `excludes` TEXT | 不要的内容，自由文本 |
| `extra_fields` TEXT | 需要额外记录的信息，自由文本，如"车型、现价、降价金额、优惠截止日期"（第 9.1 节） |
| `max_items` INTEGER | 每次最多几条，默认 6，范围 1–20 |
| `view` TEXT | 展示方式，默认 `list`（第 9.2 节） |
| `enabled` INTEGER | 1 开启 / 0 暂停，默认 1 |
| `sort_order` INTEGER | 显示顺序 |
| `created_at`、`updated_at` TEXT | `updated_at` 同时用作修改时的版本检查 |
| `updated_by` TEXT | 最近一次是谁改的：`app` / `agent`，默认 `app`（版本 2 新增） |

主题由 AI 在对话中和用户确认后建立；拾闻里可以调整设置、暂停或删除，但不提供新建。双方修改都带 `WHERE id = ? AND updated_at = ?`，影响 0 行说明对方刚改过，不覆盖。主题以表中当前数据为准，AI 不按对话记忆恢复用户删除、暂停或改过的设置。

删除主题时：主题行删除，它的历史内容保留，`items.topic_id` 置空，界面显示为"已删除的主题"。

### 6.3 `items`

AI 写的内容列：

| 列 | 说明 |
|---|---|
| `id` INTEGER 主键 | |
| `run_id` INTEGER | 哪一次运行写入的 |
| `topic_id` INTEGER | 属于哪个主题 |
| `title` TEXT 非空 | |
| `url` TEXT 非空、**唯一** | 原文链接；唯一约束同时实现去重 |
| `source` TEXT | 来源名称，如"汽车资讯" |
| `published_at` TEXT | 原文发布时间，不确定可空 |
| `summary` TEXT 非空 | AI 写的中文摘要，2–4 句 |
| `reason` TEXT | 为什么推给这位用户，一句话 |
| `importance` INTEGER | 1 一般 / 2 值得看 / 3 重要，默认 2 |
| `image_path` TEXT | 本机配图，相对 `data/attachments/` 的路径 |
| `image_url` TEXT | 原图地址，备用 |
| `extra` TEXT | 额外信息，JSON 对象，默认 `{}`，键名用主题 `extra_fields` 里的原词，值一律是字符串 |
| `collected_at` TEXT 非空 | 写入时间 |

拾闻写的用户列：

| 列 | 说明 |
|---|---|
| `is_read` INTEGER | 默认 0 |
| `is_starred` INTEGER | 默认 0 |
| `starred_at` TEXT | |
| `is_dismissed` INTEGER | 不感兴趣，默认 0 |
| `dismiss_reason` TEXT | `和主题无关`、`来源不可靠`、`内容太旧`、`重复了` 之一，可空 |
| `note` TEXT | 用户备注，AI 也会读 |
| `user_updated_at` TEXT | 用户最后一次操作这条的时间 |

约束：`extra` 和 `keywords` 加 `json_valid` 检查；`importance` 加范围检查；`dismiss_reason` 加取值检查。约束的作用是让写错的数据直接被数据库拒绝，而不是在界面上出错。

索引：`collected_at`、`topic_id`、`is_starred`。

### 6.4 `runs`（AI 写）

| 列 | 说明 |
|---|---|
| `id` INTEGER 主键 | |
| `started_at` TEXT 非空 | |
| `finished_at` TEXT | 结束时写 |
| `agent` TEXT | AI 自报的工具名，如 `Claude`、`Codex`、`WorkBuddy` |
| `trigger` TEXT | `setup`（第一次试跑）/ `manual`（用户叫的） |
| `status` TEXT | `running` / `done` / `partial` / `failed` |
| `added`、`skipped` INTEGER | 新增条数、因重复跳过的条数 |
| `images_saved`、`images_failed` INTEGER | |
| `digest` TEXT | 这一期的"今日要点"，AI 写的 1–3 句 |
| `message` TEXT | 给用户看的说明，失败或部分完成时写原因 |

AI 开始时单独插入一行 `status = running` 并立即提交，拾闻据此显示"AI 正在更新…"；收集完成后，在写入内容的同一个短事务里把这行更新为最终状态；写入失败时单独把它更新为 `failed`。拾闻用这张表显示上次更新的时间和结果（第 8.1、8.6 节），不据此判断 AI 是否"已连接"。

### 6.5 `requests`

| 列 | 谁写 | 说明 |
|---|---|---|
| `id` INTEGER 主键 | 拾闻 | |
| `kind` TEXT | 拾闻 | `deep_dive`（深入了解）/ `similar`（找类似的） |
| `item_id` INTEGER | 拾闻 | 针对哪一条 |
| `text` TEXT | 拾闻 | 用户补充的话，可空 |
| `created_at` TEXT | 拾闻 | |
| `status` TEXT | AI | `pending`（默认）/ `done` / `failed` |
| `result` TEXT | AI | 处理结果，纯文本；找到的新内容另外写入 `items`，并在这里列出标题 |
| `run_id`、`finished_at` | AI | |

### 6.6 `learned`（AI 写，拾闻可删）

| 列 | 说明 |
|---|---|
| `id` INTEGER 主键 | |
| `topic_id` INTEGER | 可空，空表示对所有主题都适用 |
| `text` TEXT 非空 | 一句话，如"常标记不感兴趣：融资消息" |
| `updated_at` TEXT | |

每个主题最多 10 条。AI 每次运行根据最近的反馈更新这张表（可以改自己写的行、删自己写的行）。

### 6.7 配图

- AI 下载原文配图，缩成最长边 640 像素以内（macOS 自带 `sips` 可以做），存到 `data/attachments/images/YYYY-MM/<链接哈希>.jpg`（链接 SHA-1 的前 16 位十六进制；配图在写库之前下载，那时还没有内容 id），把相对路径写入 `image_path`，同时把原图地址写入 `image_url`。
- 下载或缩图失败：`image_path` 留空，只写 `image_url`，并计入 `images_failed`。
- 拾闻显示顺序：`image_path`（用 `panda.files.url`）→ `image_url`（仅 https）→ 来源名称首字的色块。
- 清理：拾闻在启动时检查，未收藏且 `collected_at` 超过 180 天的内容，删除配图文件并把 `image_path` 置空，文字保留。清理在后台进行，不阻塞界面，失败只记在控制台。此功能优先级低（第 11 节）。

## 7. `AGENTS.md`

`AGENTS.md` 是 AI 每次在这个文件夹工作时的规则，以该文件为准，这里只列要点，不再重复全文：

- **四类事**：开始使用、管理主题、更新简报、修改拾闻本身。
- **开始使用**：先读数据库。已有主题就复述并问要调整、新增还是直接更新；没有就请用户描述想关注什么。整理成主题后用平常话一次给用户确认（额外记录按用户的行业和用途来定），用户同意后才写库，然后马上更新一期（`trigger = setup`），并提醒用户以后在对话里说“更新简报”。不创建定时任务。同一句开场白可能重复发送（换了 AI 工具或对话丢失），每次都按数据库现状继续。
- **管理主题**：只在用户于对话中明确要求时写 `topics`，先确认改动；带 `updated_at` 版本检查；不按对话记忆恢复用户的修改。
- **更新简报**：第 3 步读取时识别用户在拾闻里改过的主题，以新设置为准并清理冲突的 `learned`；没有开启的主题时只记录运行并请用户描述想关注什么。其余流程和写入规则不变：开始单独提交，收集期间不持有写事务，结果一个短事务提交，只新增内容，不改用户列。

## 8. 界面

草图在 `docs/design/`。草图表达结构、内容和文案方向；视觉以紧凑为原则：正文 13px，行高 1.5，页面边距 14–18px，控件高 28–32px。

### 8.1 全局

- 左侧导航：简报、全部、收藏、主题、记录和「在 AI 里使用拾闻」（第 8.7 节）。简报的更新状态在标题栏，其他页面的更新状态在侧栏。点状态进入「记录」。
- 更新状态来自运行记录：没有记录时显示「还没有更新记录」，最近一条运行在 1 小时内仍进行时显示「AI 正在更新…」，超过 1 小时显示「上次更新可能中断了」，失败时显示「上次更新没有完成」，完成后显示上次更新时间。
- **重新载入**：简报页用「重新载入」读取已收录的内容，其他页面用「刷新」。窗口重新获得焦点或页面重新可见时会自动刷新，同时保留正在编辑的输入。
- 有新内容时（刷新后比之前多），导航「简报」旁显示新条数。
- 所有列表分页或按需加载，每次 50 条，不一次性读全部历史。

### 8.2 简报（`01-today.html`）

- 显示最近一期有内容的简报。按设备本地时间，这期在当天完成时标题为「今日简报」，跨天时标题为「最新简报」。
- 页眉标明本期实际更新时间、总条数和未读数。当天还没更新，或已检查但暂无新增时，状态显示在右侧，继续展示最近一期。
- 没有任何内容时显示「还没有内容」和 AI 使用引导。零未读时「全部标为已读」禁用。
- 宽窗口内，左边列表与右边阅读区宽度约为 1∶2，各自可滚动。主题标签直接显示在搜索框下方，最多两行，当前选中主题保持可见。其余主题可通过「更多」搜索、滚动和选择。「全部主题」清除主题筛选。窄窗口改为单列。
  - 列表按主题分组。行高随最多两行的标题变化，显示来源、未读圆点和收藏标记。已确认的照片或插图在行尾显示缩略图（58×42）。有 `extra` 时在标题下显示最多 3 个额外信息标签。
  - 双栏默认预览首条未忽略的内容，点开时才标为已读。阅读区先展示标题、来源、摘要和推荐理由，配图折叠在备注下方。
  - 收藏在标题区。打开原文、复制链接、不感兴趣和 AI 请求在摘要后，窄窗口下分组换行。
  - 不感兴趣后：这条在列表里折叠成一行"已忽略 · 撤销"，右边显示四个原因按钮（可选、可改）。
  - 备注失焦时自动保存，旁边显示"AI 下次更新时会看到"。
- 主题的 `view` 不是 `list` 时，该主题分组使用对应的展示方式（第 9.2 节）。

### 8.3 全部（`02-all.html`）

- 搜索：标题、摘要、备注，模糊匹配。
- 日期：今天 / 近 7 天 / 近 30 天 / 自定义（起止日期）。
- 最近 14 天的日期条：每天一格，显示条数柱和数字，点击只看那天，当前范围高亮。
- 主题、状态（全部、未读、收藏、已忽略）、排序（最新、最早）。
- 当前筛选显示成可移除的标签，加"清除全部"，右侧显示结果条数。
- 结果按日期分组，每行：小缩略图（56×40）、标题（搜索词高亮）、一行摘要、主题标签、来源 · 时间、收藏标记。点击打开阅读面板（可复用今日的右侧面板，或跳到对应位置，由实现者选择）。

### 8.4 收藏（`03-favorites.html`）

- 卡片网格（每张最小宽 220px），图片 16:9；也可切换为列表。
- 卡片：主题、标题、来源 · 发布日期、备注（如有）、收藏于何时。
- 筛选：主题、"有备注"；搜索标题和备注；排序：收藏时间、发布时间。

### 8.5 主题（`04-topics.html`）

- 主题由 AI 建立。页面不提供新建表单和示例主题；标题栏有文字链接"想关注新的内容？告诉你的 AI"，打开第 8.7 节弹窗并定位到"开始使用"。没有主题时显示"主题由你的 AI 帮你建立。告诉它你想关注什么就行"。
- 左边主题列表（名称、描述、开启 / 暂停、最近一次条数、收藏数），右边编辑表单。表单标题下用小字标注来源："AI 按你的要求创建 / 修改 · 时间"或"你在 某时间 修改过"。
- 表单：主题名称、每次最多几条、显示顺序、开启、我关心什么、关键词、优先的来源、不要的内容、**额外记录**、**展示方式**（下拉，默认"列表"，列出 `app/views/` 里已有的方式）。保存后提示"已保存，AI 下次更新时按新的设置收集"。若保存时 AI 刚改过这个主题，提示用户刷新后再改，不覆盖。
- "AI 从你的反馈里学到的"：列出 `learned`，每条可删除。
- 删除主题要确认，并说明历史内容、收藏和备注会保留，这个主题学到的偏好会一并删除。

### 8.6 记录（草图 `05-updates.html` 为修订前版本）

- 标题"记录"，说明"AI 每次更新都会在这里留下一条记录。想看新内容，在和 AI 的对话里说'更新简报'。"
- 最近一次运行在进行中、可能中断或没有完成时，表格上方显示一行提示和 AI 写的 `message`。
- 运行记录表：时间、AI 工具、方式（首次 / 手动）、结果（新增、跳过、配图、说明）、状态。最近 30 条，可加载更多。没有记录时显示"还没有记录"和"在 AI 里使用拾闻 →"。

### 8.7 在 AI 里使用拾闻（弹窗，取代原"第一次打开"引导）

提示词只放在这一个弹窗里（今日空状态另外直接显示「开始使用」那句和复制按钮），从侧栏、今日页、主题页、记录页打开。路径来自 `(await panda.context.get()).projectRoot`，附"复制路径"。

1. **开始使用 · 新增或调整主题**
   > 请在 `<路径>` 工作，先读 AGENTS.md，再按其中「开始使用」和我一起设置拾闻。如果你读写不了这个文件夹，先告诉我。

   注明"已经发过、设置好的，不用再发。换了 AI 工具或对话丢失时，再发一次即可。"AGENTS.md 保证重复发送无害。
2. **常见问题**：想看新内容怎么办（在 AI 对话里说“更新简报”）；换了 AI 工具或对话找不到了（把开始使用那句话再发一次）；想改拾闻的样子（点窗口上的「按你的想法改」）。

### 8.8 异常提示

| 情况 | 提示 |
|---|---|
| 数据库里有不完整的内容（如 `extra` 不是对象） | 跳过这条，"记录"里显示"有 N 条内容格式不对，已跳过" |
| 配图文件不存在 | 静默改用原图地址或来源首字，不报错 |
| 运行失败 | 侧栏状态变红，"记录"显示 AI 写的 `message` |
| 数据库读取失败 | 页面中央说明"暂时读不到数据"，附"重试"，不清空已显示的内容 |
| 启动失败（建表或升级出错、程序版本比数据旧等） | 显示"拾闻打不开"和真实出错信息，附"复制"和"重试"，引导用户把信息交给自己的 AI；拾闻不自己修数据 |

## 9. 通用版与定制

不同信息关注点不同（车价关心现价和优惠截止，出行关心线路和生效时间）。拾闻做一个通用版，再留出两层定制。

### 9.1 第一层：额外信息（不改程序）

用户在主题里写"额外记录"，AI 把这些信息写进 `items.extra`，通用列表把它们显示成标签。例如车价主题写"车型、现价、降价金额、优惠截止日期"，列表行显示"现价 15.98 万 · 降 0.8 万 · 截止 11/30"。大部分主题做到这一层就够了。

### 9.2 第二层：展示方式（AI 改程序）

- 程序里有一个清楚的"展示方式"登记处：`app/views/` 下每种展示方式一个文件，`app/views/index.js` 登记 `id → 名称、渲染函数`。
- 通用列表 `list` 是默认方式。一个主题选了别的方式后，今日和全部页面里该主题的内容用这种方式渲染；阅读面板、收藏、搜索不受影响。
- 新增一种展示方式 = 新增一个文件 + 在登记处加一行。不改通用部分。
- 在 `docs/design.md` 或单独的 `docs/views.md` 写清楚怎么新增，AI 修改前先读。

### 9.3 示范：车价对比表

第一版**不内置**车价对比表。它用来演示第二层：用户用「按你的想法改」对 AI 说"车价主题做成对比表"，AI 新增 `price-table` 展示方式。草图 `07-car-generic.html`（通用列表 + 额外信息标签）和 `08-car-custom.html`（定制后的对比表）展示改前改后。实现者在完成通用版后，可以自己按这个说法试做一次，用来检验第二层设计是否顺手，结果作为报告的一部分。

需要改表结构的定制（比如把"现价"升级成正式数字列以便排序），按这个顺序：程序里加升级步骤 → `meta.schema_version` 加一 → 更新 `docs/database.md` → 必要时更新 `AGENTS.md` 的写入说明。只加列、加表，不删已有的；必须删除或清空数据时，先向用户说明影响并取得同意。

## 10. 不做的

- 调起 AI、读取 AI 会话、定时调度、定时更新、「现在更新」按钮、推送通知。
- 自己联网抓取或调用任何 AI 接口。
- 中间 JSON 文件、文件变化监听。
- 账号、同步、多设备。
- 全文搜索引擎（数据量在几万条内，模糊匹配足够）。
- 内置车价对比表或其他主题专属界面（第 9.3 节）。

## 文件和数据

```text
panda.json             熊猫小抽屉应用清单
AGENTS.md              AI 日常更新与写入规则
app/                   HTML、CSS、原生 ES 模块，无构建步骤
docs/design.md         产品与实现约定
docs/database.md       数据表、字段与写入分工
docs/views.md          扩展主题展示方式
docs/design/           静态界面草图
data/main.sqlite       本机数据库（首次打开后创建，不进 Git）
data/attachments/      本机配图缩略图（不进 Git）
```


AI 开始时单独记录运行状态，在事务外完成搜索、请求处理、下载和缩图，再以一个短事务提交结果，避免影响同时使用的界面。AI 只新增内容，不覆盖用户收藏、忽略和备注。详细约束见 `AGENTS.md` 和 `docs/database.md`。


本应用不引入前端框架或构建工具。代码版本不包含 `data/`；Git 不能代替数据备份。

改动数据库相关代码后，可以用带 `node:sqlite` 的 Node.js 运行数据保护检查，它使用独立的内存数据库，不会打开 `data/main.sqlite`：

```sh
node --test --test-concurrency=1 tests/db.test.mjs
```
